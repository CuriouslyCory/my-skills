# Issue #20 — Multi-user auth via better-auth

## Decision recorded

better-auth is the accepted auth stack (PRD `tasks/prd-hosted-service-architecture.md`
Open Question 1 / D-1 resolved by the maintainer). GitHub OAuth + email/password.
better-auth `1.4.0-beta.9` is already in the pnpm catalog; this issue activates it.

## Env var mapping (documented in `.env.example`)

better-auth reads `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` by convention. We map the
existing provided secret: pass `secret: AUTH_SECRET` and `baseURL: BETTER_AUTH_URL`
explicitly to `betterAuth()` so we keep the existing `AUTH_SECRET` name. GitHub creds use
the provided `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`. No new secret values invented.

- `AUTH_SECRET` — signing secret (existing).
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` — GitHub OAuth app (provided).
- `BETTER_AUTH_URL` — base URL of the web app (e.g. `http://localhost:3000`). Optional
  locally; defaults to `http://localhost:3000`.

## Local vs multi-user mode detection

`isMultiUserAuthEnabled()` = both `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` are set.
- When **false** (local self-hosted SQLite, no OAuth): auto-provision a single local user;
  `getSession()` returns it without any login; middleware lets everything through. This
  preserves the existing zero-signup local workflow (replaces the old
  `isAuthEnabled() === false` short-circuit that keyed off `ADMIN_USER`).
- When **true** (hosted): enforce login. Email/password sign-up + GitHub OAuth both work;
  middleware redirects unauthenticated users to `/login`.

## Database (both dialects, behind the #19 schema switch)

Add four better-auth core tables to BOTH `packages/db/src/schema.sqlite.ts` and
`schema.pg.ts`, exported through the `active` switch in `schema.ts` (typed against the
SQLite reference, pg substituted at runtime). Field property keys are camelCase to match
better-auth's model fields; DB columns are snake_case.

- `user`: id, name, email (unique), emailVerified (bool), image, createdAt, updatedAt
- `session`: id, expiresAt, token (unique), ipAddress, userAgent, userId→user, createdAt, updatedAt
- `account`: id, accountId, providerId, userId→user, accessToken, refreshToken, idToken,
  accessTokenExpiresAt, refreshTokenExpiresAt, scope, password, createdAt, updatedAt
- `verification`: id, identifier, value, expiresAt, createdAt, updatedAt

SQLite: booleans `integer({mode:"boolean"})`, dates `integer({mode:"timestamp"})`.
Postgres: `boolean`, `timestamp(withTimezone)`.

## Migrations (mirror #19)

- SQLite: `pnpm db:push` (drizzle-kit push, no committed migration files — matches #19).
- Postgres: `pnpm --filter @curiouslycory/db generate:pg` to emit a committed
  `drizzle/pg/0001_*.sql` migration + snapshot; `migrate:pg` applies it.

## packages/auth (re-implemented on better-auth)

- `env.ts`: add `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `BETTER_AUTH_URL` (all optional);
  keep `AUTH_SECRET`. Drop `ADMIN_USER`/`ADMIN_PASSWORD`.
- `src/index.ts`: build `auth = betterAuth({ database: drizzleAdapter(db, { provider, schema }),
  emailAndPassword: { enabled: true }, socialProviders: github (only when configured),
  secret, baseURL })`. `provider` = `dbDialect === "postgres" ? "pg" : "sqlite"`.
  Export: `auth`, `Session` type, `isMultiUserAuthEnabled()`, `ensureLocalUser()`,
  `getLocalSession()`. No Next import here (framework-agnostic); Next cookie flow is handled
  by the route handler's Set-Cookie responses, so the `nextCookies` plugin is not required.

## packages/api

- `trpc.ts`: import `Session` from `@curiouslycory/auth`; context unchanged;
  `protectedProcedure` unchanged — now `ctx.session.user.id` is available.
- `router/auth.ts`: reduce to `getSession` query (returns `ctx.session`). Remove
  jose `login`/`logout`/`validate`. Auth actions now go through the better-auth client.
- `test-utils.ts`: default session becomes `{ user: { id, email, name } }`.

## apps/web

- `src/app/api/auth/[...all]/route.ts`: `export const { GET, POST } = toNextJsHandler(auth.handler)`.
- `src/auth/server.ts`: `getSession()` → local mode returns `getLocalSession()`; else
  `auth.api.getSession({ headers })` mapped to `Session`.
- `src/auth/client.ts`: `createAuthClient()` (email/password + GitHub social).
- `middleware.ts`: local mode → `next()`; else use `getSessionCookie(request)` to gate,
  redirect to `/login` when absent. `/login`, `/signup`, `/api/auth`, `/api/trpc` public.
- `(auth)/login/page.tsx` + `login-form.tsx`: email/password sign-in + "Continue with
  GitHub" button; link to sign-up.
- `(auth)/signup/page.tsx` + `signup-form.tsx`: email/password sign-up.
- `auth/actions.ts`: removed (jose cookie helpers gone).
- `auth-showcase.tsx`: show `session.user.name`/email + a sign-out button.
- `env.ts`: extend with new auth env (via `authEnv`).
