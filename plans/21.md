# Issue #21: Per-user data scoping

Scope all library data to the owning user so multiple accounts can share one
deployment. Build on #20 (`ctx.session.user.id` available in routers, local mode
auto-provisions a fixed local user) and #19 (dialect-aware schema, `drizzle/pg`).

## Schema changes (BOTH dialects, kept in sync)

`packages/db/src/schema.sqlite.ts` and `packages/db/src/schema.pg.ts`:

- **skills**: add `userId` (`user_id`) text NOT NULL, `references(() => user.id, { onDelete: "cascade" })`.
  - Remove inline `.unique()` from `name` and `dirPath`.
  - Add table-level `unique().on(table.userId, table.name)` and `unique().on(table.userId, table.dirPath)`.
- **variations**: NO column change. Scoped via parent skill's `userId` (cascade delete already removes a skill's variations). There is no variations router/query path in the codebase, so scoping is enforced at the skill boundary.
- **favorites**: add `userId` NOT NULL cascade. Change `unique().on(repoUrl, skillName)` to `unique().on(userId, repoUrl, skillName)`.
- **compositions**: add `userId` NOT NULL cascade. (No existing unique constraint.)
- **config**: add `userId` NOT NULL cascade. Remove inline `.unique()` from `key`; add `unique().on(userId, key)`. Config becomes per-user preferences.

`user.id` referenced via a lazy thunk, so table declaration order is irrelevant.

## Router changes (`packages/api/src/router/`)

Every read filters by `ctx.session.user.id`; every write sets it. Read
procedures that returned data are converted from `publicProcedure` to
`protectedProcedure` so scoping is guaranteed (the dashboard is `force-dynamic`,
so no build-time prerender breaks; `prefetchQuery` swallows errors).

- **skill**: `list`, `byId` -> protected + `eq(userId)`; `create` sets userId; `update`/`delete` look up and mutate `and(id, userId)`; `syncFromDisk` passes userId.
- **artifact**: `list`, `listByCategory`, `byId` -> protected + userId filter; `create` sets userId; `update`/`delete` scoped; `syncFromDisk` passes userId.
- **favorite**: `add`/`remove`/`toggle` scope existence checks and deletes by userId and set userId on insert; `isFavorited`/`list`/`stats` -> protected + userId filter (all counts, topRepos). `syncConfigToFile(db, userId)`.
- **composition**: `list`/`byId`/`preview`/`exportMarkdown` -> protected; composition rows filtered by userId; fragment skill lookups also filtered by userId (no reading another user's skill via a fragment id). `create` sets userId; `update`/`delete` scoped.
- **config**: `get`/`getAll` -> protected + userId filter; `set` scopes existence + update by `and(key, userId)`, sets userId on insert. `syncConfigToFile(db, userId)`.
- **search** (router): `query` -> protected, passes userId to `searchSkills`.
- **git**: left as-is (filesystem-coupled, local-only for this slice).

## Library helpers

- `packages/db/src/search.ts`: add optional `userId?` to `SearchSkillsParams`. When present, filter the empty-query path (`eq(skills.userId, userId)`), the SQLite FTS branch (`AND s.user_id = ?`), and the Postgres branch (`AND skills.userId = ?`). The search router always supplies it, so API-level scoping is guaranteed; the param stays optional so the low-level util and its dialect unit tests remain usable.
- `packages/api/src/lib/disk-sync.ts`: `scanAndSync(repoPath, db, userId)` scopes the dirPath lookup and the stale-removal sweep to the user and sets userId on inserts.
- `packages/api/src/lib/config-sync.ts`: `syncConfigToFile(db, userId)` filters config and favorites by userId (per-user correctness for the local config.json; hosted gating finalized later).

## Local mode

No special-casing in routers. `apps/web/src/auth/server.ts` already resolves the
auto-provisioned local user (`local@my-skills.local`) via `getLocalSession()` when
OAuth env is absent, so `ctx.session.user.id` is that user's id and every scoped
query maps to it automatically.

## Migrations

- SQLite: `pnpm --filter @curiouslycory/db push` (db:push path) against a
  worktree-local `DB_PATH`.
- Postgres: `pnpm --filter @curiouslycory/db generate:pg` produces
  `drizzle/pg/0002_*.sql` + snapshot (generate does not need a live DB).

## Tests

- `packages/api/src/test-utils.ts`: add `user_id TEXT NOT NULL DEFAULT 'test-user'`
  to skills/favorites/compositions/config test tables and the new per-user unique
  constraints. The default keeps existing raw-insert fixtures owned by the default
  caller (`test-user`) so legacy tests pass unchanged; the real schema has no such
  default (routers always set userId explicitly).
- New `packages/api/src/router/__tests__/scoping.test.ts`: two callers (userA,
  userB). Assert each user's `list`/`byId`/`stats`/`search`/`config` returns only
  their own rows; a user cannot read/update/delete the other's records; per-user
  unique constraints allow the same name/key for different users but reject
  duplicates for the same user; local-user id maps correctly.
- Extend `packages/db/src/__tests__/search.test.ts` with a userId-filter case
  (SQLite result filtering + Postgres compiled-SQL assertion).
