## Findings (investigation)

- `packages/db/src/client.ts` eagerly does `import Database from "better-sqlite3"` at
  module top level. This loads the native addon even in `postgres` mode. It is the
  ONLY eager value import of `better-sqlite3` in runtime (non-test) source.
  - `drizzle-orm/better-sqlite3` does NOT require the `better-sqlite3` package (only
    drizzle-internal modules + type imports), so `import { drizzle as drizzleSqlite }`
    is safe and does not touch the native addon.
  - `fts.ts`, `types.ts`, `search.ts` only use `import type` of better-sqlite3 (erased).
- `apps/web/next.config.js` already sets `serverExternalPackages: ["better-sqlite3"]`
  so webpack does not bundle the native `.node`. It stays a runtime require.
- Real env var names the code reads (packages/auth/env.ts, src/index.ts):
  `AUTH_SECRET` (maps to better-auth `secret`), `BETTER_AUTH_URL`, `GITHUB_CLIENT_ID`,
  `GITHUB_CLIENT_SECRET`. The issue text says `BETTER_AUTH_SECRET`; the real name is
  `AUTH_SECRET`. Document the real name.
- `apps/web/src/env.ts` validates `DEPLOY_MODE` and extends `authEnv()` (auth vars
  optional) + `vercel()`. It does NOT yet validate `DB_DIALECT`/`POSTGRES_URL` nor the
  hosted-mode requirement set.
- Postgres migration workflow: `pnpm --filter @curiouslycory/db migrate:pg` (drizzle-kit
  migrate, config `drizzle.pg.config.ts`, needs `DB_DIALECT=postgres` + `POSTGRES_URL`).
  Migrations committed in `packages/db/drizzle/pg` (0000..0003).
- README deploy section (lines ~315-330) is stale: Deploy button env list and table
  reference Discord OAuth (`AUTH_DISCORD_ID`/`AUTH_DISCORD_SECRET`) which does not exist
  (code uses GitHub) and omits `DB_DIALECT`/`DEPLOY_MODE`/`BETTER_AUTH_URL`/GitHub vars.
- PAT bearer auth: tRPC context (`packages/api/src/trpc.ts`) falls back to
  `resolveTokenSession(db, authorization header)`, so a `Authorization: Bearer <token>`
  authenticates any `protectedProcedure`. This is the `ms login` equivalent to verify.

## Mechanism: better-sqlite3 not required at build in Postgres mode

1. In `packages/db/src/client.ts`, load `better-sqlite3` lazily via `createRequire`
   INSIDE `createSqliteClient()` only. `db` stays synchronous. In `postgres` mode
   `createSqliteClient` is never called, so the native addon is never required at
   module load, build, or runtime.
2. Keep `serverExternalPackages: ["better-sqlite3"]` so webpack leaves it as an
   external runtime require (never bundled).
3. Keep `better-sqlite3` a normal dependency (tests + local SQLite need it; Vercel
   downloads the linux prebuilt binary, no native compile). The lazy require is what
   guarantees a postgres build/runtime never loads it.

Proof plan: build the web app with `DB_DIALECT=postgres` while the better-sqlite3
native addon (`build/Release/better_sqlite3.node`) is temporarily renamed; the build
must still succeed. Restore the addon afterward.
