# Plan: #28 GitHub connector (incremental repo scope)

## Goal

Let a user optionally connect GitHub with `repo` permissions so the service can
publish on their behalf. Add a Settings "Connectors" section using better-auth's
GitHub provider with INCREMENTAL repo scope, store connector state per user,
support disconnect, and add an octokit-backed lib in `packages/api` that resolves
an authenticated Octokit client for the current user.

## Decision (do not re-open)

v1 uses the OAuth app with INCREMENTAL OAuth scope, NOT a GitHub App and NOT
fine-grained PATs (PRD Non-Goals: "No GitHub App (webhooks, installations) —
OAuth token publishing only for v1"). Recorded here per instruction.

## How incremental repo scope is requested (base sign-in stays minimal)

- Base sign-in is unchanged: `signIn.social({ provider: "github", callbackURL })`.
  The GitHub provider in `packages/auth/src/index.ts` has NO explicit `scope`, so
  better-auth uses its default GitHub scopes (`read:user user:email`). We do NOT
  touch that config, so base sign-in never requests `repo`.
- Connecting the connector uses better-auth's incremental authorization endpoint
  `linkSocial` (client `authClient.linkSocial`, server path `/link-social`),
  which accepts a `scopes: string[]` param. We call
  `authClient.linkSocial({ provider: "github", scopes: ["repo"], callbackURL: "/settings" })`.
  better-auth starts a fresh GitHub authorize with `repo` added, and on callback
  updates the EXISTING `account` row (accessToken + scope) for the user. This
  keeps repo scope OUT of the sign-in path and only requested on explicit consent.

## Where connector state lives (reuse the better-auth `account` row — no new table)

- The better-auth `account` table (both dialects, `schema.sqlite.ts` +
  `schema.pg.ts`) already stores per-provider `accessToken`, `refreshToken`,
  `scope`, and expiry. That IS the connector state (linked account + granted
  scopes), already scoped by `userId` FK to `user.id`.
- Therefore NO new table and NO new migration are needed. This is the preferred
  path per the task ("prefer reusing the better-auth account row's token+scopes;
  add a table only if genuinely needed"). Documented as an explicit decision.

## The octokit github-connector lib (`packages/api/src/lib/github-connector.ts`)

Reads the token directly from the DB via drizzle (userId-scoped) — it does NOT
import the better-auth runtime, respecting the #20 Edge/API import constraint.

- `GITHUB_PROVIDER_ID = "github"`, `REPO_SCOPE = "repo"`.
- `GithubConnectorError extends Error` with a discriminant
  `reason: "not_connected" | "missing_scope" | "token_revoked"` and a stable
  `code` string, so callers can map to distinct, actionable tRPC errors.
- `parseScopes(scope: string | null): string[]` — splits GitHub's space/comma
  scope string.
- `getGithubAccount(db, userId)` — returns the account row or null.
- `resolveGithubConnection(db, userId)` — returns `{ accessToken, scopes }` or
  throws `not_connected` (no row / no token) / `missing_scope` (no `repo`).
- `createGithubClient(accessToken, deps?)` — builds an `Octokit` (factory
  injectable for tests).
- `assertGithubTokenValid(octokit)` — calls `users.getAuthenticated()`; maps a
  401 to `token_revoked` (actionable: reconnect), rethrows others.
- `getAuthenticatedGithubClient(db, userId, deps?)` — resolve + create + verify;
  the one-call entry the publish feature (#29) will use.

Two distinct error surfaces (acceptance):
(a) not connected / repo scope not granted -> `not_connected` / `missing_scope`.
(b) token revoked/invalid on GitHub (401) -> `token_revoked`.

## Router (`packages/api/src/router/github.ts`, mounted as `github` in root)

- `status: protectedProcedure.query` — reads the account row (userId-scoped),
  returns `{ connected, hasGithubLogin, scopes, login? }`. Never throws for the
  not-connected case (returns `connected: false`).
- `verifyConnection: protectedProcedure.mutation` — resolves + pings GitHub;
  returns `{ login }` or throws a mapped `TRPCError` (FORBIDDEN for
  not_connected/missing_scope, UNAUTHORIZED for token_revoked) with actionable
  messages. Exercises both error paths and lets the UI test the live token.
- `disconnect: protectedProcedure.mutation` — clears `accessToken`,
  `refreshToken`, `scope`, expiries on the github account row (userId-scoped,
  `db.update(...).where(userId AND providerId=github)`). This forgets our stored
  publish token without deleting the row, so GitHub LOGIN still works and the
  user is never locked out. GitHub-side grant is not revoked (see Risks).

`TRPCError` mapping lives in the router, keeping the lib framework-agnostic.

## Connectors UI (`apps/web/src/app/_components/settings-page.tsx`)

New `ConnectorsSection` card added to `SettingsContent`:
- Uses `trpc.github.status` to render state.
- Not connected / no repo scope -> "Connect GitHub" button calling
  `authClient.linkSocial({ provider: "github", scopes: ["repo"], callbackURL: "/settings" })`.
- Connected -> show granted scopes + login, a "Verify" button
  (`trpc.github.verifyConnection`) and a "Disconnect" button
  (`trpc.github.disconnect`, AlertDialog confirm, matching the Favorites remove
  pattern). Toasts on success/error.
- Prefetch `trpc.github.status` in `settings/page.tsx`.
- Only meaningful in multi-user mode; in local mode there is no github account
  row, so it simply shows the not-connected state (harmless).

## Error surfaces (actionable, not generic 500)

- not_connected: "GitHub is not connected. Connect it in Settings > Connectors."
- missing_scope: "GitHub is connected but the 'repo' scope was not granted.
  Reconnect to grant repo access."
- token_revoked: "The GitHub token is no longer valid (revoked or expired).
  Reconnect GitHub." (mapped to UNAUTHORIZED)

## Risks / notes for #29 (publish via `ms publish`)

- #29 consumes `getAuthenticatedGithubClient(db, userId)` for an authenticated
  Octokit; handle its `not_connected` / `missing_scope` / `token_revoked` errors.
- Disconnect forgets our stored token but does NOT revoke the grant on GitHub's
  side (would need the OAuth app client secret + `DELETE /applications/{id}/grant`).
  Documented; the token_revoked path handles user-initiated external revocation.
- Live repo-scope round-trip needs the OAuth app to have callback
  `http://localhost:3000/api/auth/callback/github` registered and to permit
  `repo` scope (pending human action carried over from #20).
