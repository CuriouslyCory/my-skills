# Plan: `ms apply` + postinstall hook mode (issue #18)

## Goal
Add a non-interactive, idempotent `ms apply` command that reconciles installed
skills to `.my-skills.json` (github + local sources), plus a documented
`postinstall` hook recipe that degrades safely.

## Files to touch
- `apps/cli/src/commands/apply.ts` (new) - command wiring, flags, exit codes,
  hook safety, JSON output, non-interactive agent resolution, local source
  support.
- `apps/cli/src/program.ts` - register the new command.
- `apps/cli/tests/commands/apply.test.ts` (new) - reconcile, exit codes, hook
  skips, frozen, json.
- `README.md` - "Use as a dev dependency" section (recipe + env flags).
- `apps/cli/README` table / CLI reference row in root README.

## Reconcile algorithm (per skill, manifest is source of truth)
`planSkillAction(name, entry, targetDir)` reads only disk (no network):
- destPath missing -> `install`
- destPath present, `computeSkillHash(destPath) !== entry.computedHash` -> `update`
- else -> `noop`

Execution (non-frozen):
- `noop`: ensure agent adapters/symlinks exist (idempotent), no fetch.
- `install`/`update`: resolve source, (rm for update), `installSkill`, ensure
  adapters. If freshly installed hash differs from the manifest hash (upstream
  drift, no commit pinning exists), update that entry's `computedHash` +
  `installedAt` and persist so re-runs are idempotent (second run = all noop).

Source resolution:
- `github`: `sourceToGitHub` -> `fetchRepo` -> `resolveSkill` (unauthenticated
  shallow clone, existing path).
- `local`: `resolve(projectRoot, entry.source)` -> `resolveSkill` (no network).
- other: throw unsupported.

Only `install`/`update` touch the network; an in-sync project does zero network.

## Non-interactive agent resolution (never prompt)
`manifest.agents` (validated via AgentIdSchema) -> `config.defaultAgents` ->
`detectAgents(projectRoot)`. Per skill use `entry.agents ?? fallback`.

## Project root
`process.env.INIT_CWD ?? process.cwd()` so postinstall (running inside
node_modules/my-skills) targets the host project, not the package dir.

## Flags + exit codes
- `--frozen`: no mutations; if any skill would install/update -> exit 2, else 0.
- `--json`: machine-readable summary + per-skill actions.
- `--hook`: postinstall mode. Skip conditions + safe degradation.
- default (non-frozen, non-hook): perform changes; any hard failure -> exit 1;
  else 0.

Hook safety (only when `--hook`):
- `MY_SKILLS_SKIP=1` -> skip, exit 0.
- `CI` set and `MY_SKILLS_CI !== "1"` -> skip, exit 0.
- no `.my-skills.json` -> skip, exit 0.
- any error (network/resolve/install) -> warn + exit 0 (never break host install).

## Verification steps
1. `pnpm install`, then `pnpm --filter my-skills lint typecheck test`, plus
   repo-wide `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`.
2. Unit tests: plan actions, exit-code mapping, hook skips, frozen exit 2,
   json shape, local + github, idempotency (second run all noop).
3. End-to-end scratch project under the worktree: a manifest with a local
   source skill; run built CLI `apply`; assert `.agents/skills/<name>` and
   `.claude/skills/<name>` symlink appear; re-run is noop; `--frozen` on a
   dirty tree exits 2, on a clean tree exits 0.
