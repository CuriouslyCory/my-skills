# Plan: #26 Hosted web persistence + DEPLOY_MODE gating

## Goal
Make the web-ui persist all saves to the database in hosted mode, and gate every
filesystem-coupled feature behind a `DEPLOY_MODE=local|hosted` flag. Local mode
(default) stays byte-for-byte unchanged.

## Investigation findings
- `content` column already exists (NOT NULL) on `skills` in BOTH dialects; `dirPath`
  (`dir_path`) is ALREADY nullable in BOTH dialects. So NO schema change and NO
  migration 0004 are required. Hosted skills/artifacts simply persist `dirPath = null`.
  Postgres and SQLite both treat NULLs as distinct in the `(userId, dirPath)` unique
  index, so many hosted rows with null dirPath per user do not collide.
- Filesystem coupling lives in exactly these call sites:
  - `skill.create` / `artifact.create`: `mkdir` + `writeFile` SKILL.md, then store `dirPath`.
  - `skill.update` / `artifact.update`: `writeFile` guarded by `if (existing.dirPath)`.
  - `skill.delete` / `artifact.delete`: `rm` guarded by `if (existing.dirPath)`.
  - `skill.syncFromDisk` / `artifact.syncFromDisk`: call `scanAndSync`.
  - `config.set`, `favorite.add/remove/toggle/reorder`: fire-and-forget `syncConfigToFile`.
  - `apps/web/src/app/(dashboard)/skills/page.tsx`: server component calls `scanAndSync`.
  - `git` router (`GitService` on `ctx.repoPath`) + the git page UI + the disk-sync
    buttons which live only inside `git-status.tsx` (on the git page).
- `composition` router is already DB-only (no filesystem). Favorites/search/settings
  are already per-user (#21) and dialect-agnostic (#19); no functional change needed.
- Client sidebar (`sidebar.tsx`) is a client component and needs the mode as a prop.

## DEPLOY_MODE: define / validate / consume
- New edge-safe resolver `packages/api/src/lib/deploy-mode.ts`:
  `resolveDeployMode(value = process.env.DEPLOY_MODE)` returns `"hosted"` only when the
  value is exactly `"hosted"`, else `"local"` (unknown -> local, mirrors `resolveDialect`).
  Helpers `isLocalMode()` / `isHostedMode()`. Read at CALL time (not module load) so tests
  can toggle. Exported from `@curiouslycory/api`.
- Web validation/documentation: add `DEPLOY_MODE: z.enum(["local","hosted"]).default("local")`
  to the server schema in `apps/web/src/env.ts` (US-010 wants it validated there). Add to
  `.env.example`.
- Server consumption (routers): call `resolveDeployMode()` at each gating point.
- Client consumption (UI): the dashboard layout (server) reads `env.DEPLOY_MODE` and passes
  `deployMode` down through `AppShell` -> `Sidebar`/`MobileSidebar` to filter the Git nav
  item. No new client env var; a plain string prop keeps it edge-safe and simple.

## Gating points
1. `skill.create` / `artifact.create`: if local -> current mkdir/writeFile + `dirPath`;
   if hosted -> skip disk, insert with `dirPath: null`.
2. `skill.update` / `artifact.update`: wrap the SKILL.md write in `isLocalMode() && existing.dirPath`.
3. `skill.delete` / `artifact.delete`: wrap the `rm` in `isLocalMode() && existing.dirPath`.
4. `skill.syncFromDisk` / `artifact.syncFromDisk`: in hosted return `{added:0,updated:0,removed:0}`
   without touching disk.
5. `config.set`, `favorite.*`: only call `syncConfigToFile` when `isLocalMode()`.
6. `skills/page.tsx`: only `scanAndSync` when local (in addition to the existing session guard).
7. `git` router: add `localOnly*Procedure` variants (pass-through middleware that throws
   `PRECONDITION_FAILED` only in hosted). Git procedures switch to them so the router is fully
   disabled server-side in hosted (defense-in-depth; PRD US-001). Pass-through in local keeps
   behavior identical.
8. UI: git nav item hidden in hosted; `git/page.tsx` calls `notFound()` in hosted. Disk-sync
   buttons live only inside the git page, so hiding the page hides them.

## Editors persist to DB in hosted; dirPath optional
`content` already persists in create/update for skill+artifact. In hosted, create simply omits
the disk write and stores `dirPath: null`; update/delete already key their disk work off
`dirPath`, which is null for hosted rows. No input-schema change needed: `dirPath` was never a
create input; it is derived. So "creating a skill in hosted mode does not require dirPath" holds
by construction.

## Schema / migration
None. `dirPath` already nullable, `content` already present, both dialects. Documented above.

## Tests (both modes)
New `packages/api/src/router/__tests__/deploy-mode.test.ts` (mocks config-sync and disk-sync):
- hosted: `skill.create` / `artifact.create` succeed with `dirPath === null`, write NO SKILL.md
  to `repoPath`, and do NOT call `syncConfigToFile`; `config.set` and `favorite.add` do NOT call
  `syncConfigToFile`; `skill.syncFromDisk` returns zeros and does NOT call `scanAndSync`.
- local: `skill.create` writes SKILL.md and sets `dirPath`; `config.set` DOES call
  `syncConfigToFile`; `syncFromDisk` DOES call `scanAndSync`.
Existing suites already exercise local behavior (default mode) and must stay green.

## Verification (both DEPLOY_MODE values)
- Node 24.14.0, `pnpm install`, seed SQLite (`rm -f data/*.db* && pnpm db:push`).
- HTTP against dev server (browser MCP may be unavailable): with `DEPLOY_MODE=hosted` confirm an
  editor save persists to DB and the git page / disk-sync controls are gone (nav hidden + /git
  404s); create a skill with no dirPath. With `DEPLOY_MODE=local` confirm git page present and
  filesystem sync runs.
- Gate: `pnpm lint`, `pnpm typecheck`, `pnpm turbo run build --filter='!@curiouslycory/web'`,
  then reseed + `pnpm --filter @curiouslycory/web build`, then `pnpm test`.

## Risks / notes for #27
- #27 sets `DEPLOY_MODE=hosted` + `DB_DIALECT=postgres` in Vercel/Neon prod. Both are independent
  flags; hosted uses the DB-only paths and disables git/disk/config-file sync.
- Git router is disabled server-side in hosted; the CLI's git-based publish flow is unaffected
  (it runs locally).
