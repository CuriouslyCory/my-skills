# Plan: Personal access tokens (#22)

Let users mint and revoke API tokens so the CLI/CI can act on their behalf. Add an
`api_tokens` table, a `token` tRPC router (create/list/revoke), Bearer-token
resolution in the tRPC context, and a web settings section. Tokens are shown in
full exactly once at creation; only a SHA-256 hash plus an 8-char prefix persist.

Builds on: #19 dialect schema, #20 better-auth (Edge/API import constraint), #21
per-user scoping, #28 github-connector (DB-direct token read pattern).

## 1. Schema (`api_tokens`, BOTH dialects)

Columns (identical names on both dialects):

- `id` text PK, `$defaultFn(crypto.randomUUID)`
- `user_id` text NOT NULL, FK -> `user.id` ON DELETE cascade (no default, per #21)
- `name` text NOT NULL
- `token_hash` text NOT NULL UNIQUE (SHA-256 hex of the full token)
- `token_prefix` text NOT NULL (first 8 chars of the full token, for display/lookup)
- `scopes` text NOT NULL default `'[]'` (JSON array, like `skills.tags`)
- `last_used_at` timestamp NULLABLE
- `expires_at` timestamp NULLABLE
- `created_at` timestamp NOT NULL default now/unixepoch

Index on `token_prefix` (narrows candidate rows before the constant-time compare).

- SQLite (`schema.sqlite.ts`): timestamps as `integer({ mode: "timestamp" })`,
  `created_at` default `sql`(unixepoch())``.
- Postgres (`schema.pg.ts`): timestamps as `timestamp({ mode: "date", withTimezone: true })`,
  `created_at` `.defaultNow()`.

Export `apiTokens` from `schema.ts` via the `active` switch.

## 2. Token generation, hashing, constant-time compare

New lib `packages/api/src/lib/token-auth.ts` (reads DB directly via drizzle, only
`import type` from `@curiouslycory/auth`; never imports the better-auth runtime, per #20):

- `TOKEN_PREFIX = "mysk_"`, `TOKEN_PREFIX_LENGTH = 8`, 32 CSPRNG bytes.
- `generateToken()` -> `{ token, tokenHash, tokenPrefix }`:
  `token = "mysk_" + randomBytes(32).toString("base64url")`,
  `tokenHash = sha256(token) hex`, `tokenPrefix = token.slice(0, 8)`.
- `hashToken(token)` -> sha256 hex.
- `extractBearerToken(header)` -> the `mysk_...` token or null (must have Bearer +
  `mysk_` prefix).
- `resolveTokenSession(db, header)` -> `Session | null`:
  1. extract token; null-guard.
  2. compute sha256 digest Buffer of the incoming token.
  3. `select` candidate rows by `token_prefix` (indexed).
  4. for each candidate: `Buffer.from(row.token_hash, "hex")`; skip if length
     mismatch; `crypto.timingSafeEqual(incomingDigest, storedDigest)` (equal 32-byte
     lengths) -> match. Constant-time; never compares plaintext.
  5. if no match -> null. If matched but `expires_at <= now` -> null (reject expired).
  6. update `last_used_at = now` for the matched row.
  7. load the `user` row, return `{ user: { id, name, email, image }, session: null }`
     — the SAME `Session` shape a cookie session yields.

## 3. Bearer resolution wiring in the tRPC context

`packages/api/src/trpc.ts`: make `createTRPCContext` async. If a cookie/local
`session` is already provided, use it unchanged; otherwise resolve from the
`Authorization` header via `resolveTokenSession(db, headers.get("authorization"))`.
Result populates the identical `ctx.session`, so `protectedProcedure` and ALL #21
`ctx.session.user.id` scoping work unchanged — a Bearer session is
indistinguishable downstream from a cookie session. Both web callers already pass
`headers` and already `await` context creation, so async is safe.

## 4. Token router (`packages/api/src/router/token.ts`)

All `protectedProcedure`, userId-scoped:

- `create({ name, scopes?, expiresAt? })` -> generate token, insert hash+prefix,
  return the FULL token exactly once plus `{ id, name, tokenPrefix, createdAt, expiresAt }`.
- `list()` -> user's tokens: `{ id, name, tokenPrefix, scopes, lastUsedAt, expiresAt, createdAt }`.
  NEVER returns `tokenHash` or the plaintext.
- `revoke({ id })` -> scoped delete `and(id, userId)`, `.returning()`; throw
  NOT_FOUND if nothing deleted (cannot revoke another user's token).

Register `token` in `root.ts`.

## 5. Settings UI

Add a `TokensSection` to `apps/web/src/app/_components/settings-page.tsx` alongside
(not disturbing) #28's `ConnectorsSection`. Create form (name), list (prefix +
last used + created), revoke via AlertDialog. On create, surface the full token
once in a copyable block with a "shown only once" warning; clear on dismiss.

## 7. Tests (`packages/api/src/router/__tests__/token.test.ts` + token-auth unit)

- create returns the full `mysk_` token once; DB persists only the hash (assert
  stored `token_hash === sha256(token)` and never equals the plaintext).
- list shows prefix + lastUsed, never the secret/hash.
- revoke works; a revoked token no longer authenticates via `resolveTokenSession`.
- a valid Bearer token resolves to the right user; #21 scoping still holds (token
  for user A cannot read user B's data).
- invalid token and expired token are rejected (null).
- constant-time: assert `timingSafeEqual` is used and lengths are equalized (unit
  test on the digest buffers; a wrong-length/garbage token returns null without throw).
- pg branch exercised via compiled-SQL/mock as prior waves did; default SQLite suite green.
